## A：固定路径验收

独立条件ID `NC123_V2_L19_EVENT3_FIRST_BATCH_160KW_ONLY_NORMAL`。动作 `[22,37]+[0]*28`：未受电区开L26，60秒合L122接回首批160 kW，其余时间等待。完整30分钟初态加每槽0/30/60秒共91请求；最多273数值入口、240秒、4 GiB，无缓存、无自动重试。全部91可靠PASS才认证正常需求供电量；任一可靠FAIL或UNKNOWN即停止，后缀保留。不得把条件性1682.333333 kWh预先当作认证结果。

此阶段于独立冻结和6项单路径软件检查后执行，结果另见实际run；只有完整通过且保存输出复核一致，才打开B执行门。

## B：一次冷启动IGRS迁移任务

- 独立条件ID `NC123_V2_L19_EVENT3_IGRS_FIRST_GAIN`，同l19故障、开发事件3、v2模型、Normal算法0和全部物理政策；改变的只是实验身份。
- 精确固定上限：累计512次逻辑请求、512次实际物理请求、1536个数值入口、240秒、4 GiB。每个实际物理请求包括初始化的3入口，预扣不退款。单进程树，禁止重试、超时后重启、增加预算或按结果调排序。
- GUARD参数：lookahead6、beam8、32分支扩展、5000生成候选、64检查候选、窗口32、普通邻域32。EARLY如被执行，保留已有固定分批生成及最多16次验证规则；同一个任务的全局计数不重置。图DP最多200000个状态/子问题，图计算30秒保护门，费用属于任务墙钟。
- 从自身冷启动认证的全等待方案建立正常供电量门槛。**A的动作、物理证书、潮流缓存、认证电量、上一轮失败点都不进入B的候选生成、排序、热启动或阈值。** A的封存结果仅作“允许启动”的前置门。
- 保留原IGRS的GUARD→EARLY关系。按用户目的增加最外层停止规则：首个完整认证方案电量严格大于本任务自身全等待电量时停止。如在GUARD已达到目的，标记`EARLY_NOT_REACHED_GOAL_STOP`，仅主张IGRS搜索前段迁移可交付方案，不声称本例验证了附加筛选收益。
- 每条完整方案仍须初态加90时序样点全部PASS；接受样点只能来自本任务。缓存仅以含动作历史的完整请求SHA精确命中，单任务私有；分别记录逻辑请求、物理请求、缓存命中和未完成请求。比v14的完整求解输入等价缓存更保守，123成本不能与历史34节点直接作为公平速度比较。
- 发现UNKNOWN或代码/证据错误停止受影响工作；预算终止保留已有证书和未完成记录。不把预算失败称为全域无解，也不追加第二次搜索。

## 迁移改动与零潮流要求

旧13/34实现不改。隔离123派生仅参数化19个负荷控制、22个开关、42动作、41状态位及相应特征维数；全可达状态枚举改为按需图计算，停止上界使用全部正常需求总量的安全松界，不伪造已遍历全状态域。乐观图路线保持原正常供电目标和状态路径末级tie；原完整优先级 `(-E,-P_final,操作数,动作序列)`、候选生成和已认证门槛筛选语义保持。

显式转换旧失败槽零基index与123状态step，完整初态不能漏。迁移一致性测试、私有缓存与预算异常软件测试必须通过，并快照实际源码/依赖/配置，再允许一次物理任务。
