日期：2026-10-31。用户明确授权暂缓大负荷、先恢复小批再分批接入，保留Beam保底，窗口和BC使用相同改动；先小规模检验，不盲目训练。本轮B仍为研究主线，但尚无新B模型，不能把公共机制或固定BC排序迁移称为B已超过同数据BC。

## 固定科学范围

使用原延期对照run `20261031T053323_555256Z_clpu_deferred_pilot`的全部8个已观察训练工况，原负荷/故障/CLPU事件/条件、30个60秒操作槽、30秒物理采样、原数值与电压/热等约束均不变。正式、tune及CLPU holdout不访问。只使用项目.venv，不改旧封存源码、配置或原始数据。

准备和接回只使用原10个整负荷二值准备位，开关仍为原9位。准备动作从原initial逐槽执行，只可暂缓尚未实际供电的负荷，占用真实规划时槽；不能免费预配置初态，不能将405/450kW负荷拆成虚拟小块，不能断开已供电负荷。未接回的负荷保持未供电并计入完整30分钟目标，不能从分母删除。首次接回才开始原CLPU衰减，等待不让未供电负荷提前衰减。

## 一次冻结的公共候选生成规则

1. 从原`initial_candidates`、原lookahead=6的纯图计划提取仅11至19开关动作的路线，按原图目标优先级及路线字典序排序，保留最多2个终态开关mask不同的代表。长度超过原6深度的路线记不可用，不截断成看似完整路线。此2代表是本版有限算法设计，不是调物理参数。
2. 对每条路线，以终态开关mask和原初态ready位确定目标供电集，识别初态尚未供电的可控整负荷，按原nominal_kw从大到小、动作ID破同值排列，构造暂缓最大1项和最大2项两个准备集合。准备按同一确定顺序逐槽关闭，随后执行共同开关路线；逐步验证原合法性与不再断供条件。裸开关路线的中间合法性只作诊断，不提前排除可能在准备后合法的计划；实际准备与接回后的完整计划必须独立通过原图合法性检查。
3. 保留完整HOLD（准备负荷暂不接回）、PARTIAL（两项中仅接回一项）、FULL（全部接回）计划。两项接回顺序固定涵盖小到大和大到小，不看新物理结果挑顺序。
4. 接回时间只取两种事前规则：NATURAL为自然相邻操作槽；ONE_TAU为相邻接回操作、以及开关路线最后操作到首次接回操作之间相隔`ceil(event.tau_seconds / slot_seconds)`槽，额外WAIT为该值减1。ONE_TAU来自既有指数曲线的一个时间常数，不修改tau、不搜索延迟值。实际复电批间隔另记，不把开关操作间隔冒充实际负荷pickup间隔。
5. 每路线最多12个去重完整计划、两路线最多24个，不超过共同32槽可见容量。生成全部后继再按完整图目标分析，不因准备/不接回方案目标低而提前剪掉其后续接回方案。超过30槽记UNAVAILABLE，不截掉接回动作；其余以WAIT补足完整30槽。所有非法、重复、无可暂缓负荷、不可用及图非改善提议分类保留。

本规则从模型与现有准备位定义构造，不使用新验证答案。所有方法使用同一完整候选生成器、去重规则、候选特征及曝光规则。

## 共同EARLY与完整GUARD

EARLY实付原INITIAL与完整WAIT基准，然后一次生成新固定候选池。候选生成、图检查和完整记录都计入该冷任务费用。本版不再执行旧16次图EXPAND；使用原最多16个完整计划VERIFY选择和最多1次YIELD，新增操作数不能与旧混合step直接当速度等价。

普通验证轮展示全部待验候选（最多24）；已完成验证次数为奇数时，共同优先展示仍有暂缓负荷且完整图目标严格高于当前已认证incumbent的HOLD/PARTIAL候选，没有则回到全部待验候选。候选不伪标为旧`prefix_wait`，原raw261/global79特征公式保留；固定BC属于新候选分布上的排序迁移，不声称重新训练适配。窗口使用原Beam排序，BC使用原seed17/41/73三个固定端点，其他信息和机制一致。

每任务随后完整运行原`BranchSearch` GUARD（256扩展及其原停止规则），不给GUARD注入新候选或缩减预算。EARLY与GUARD各独立256逻辑点，总实际点上限512；同一冷任务内可按原严格电气输入复用已付费可靠证据，跨任务/方法/历史不共享答案。最终仅在完整认证后按正常供电能量取较大，精确并列取GUARD。执行或证据错误不能被旧可行incumbent掩盖为任务成功。

## 固定32任务与条件分段

人口为8工况×〔staged_window、staged_bc17、staged_bc41、staged_bc73〕，不设PPO或虚构B臂。首个新求解前冻结全部32任务及顺序、代码、协议、实际配置、模型SHA、依赖、场景与零求解候选清单。每工况4臂按预定Latin轮转，最多2个冷worker，上一对真实退出后才派发下一对。新生成器在实际冷任务内重新计算，冻结的零求解清单只用于核对，不作为免费数值证书。

为避免单计划补验后重复跑同样候选，本轮直接做共同对照并分两段：

- 第一段是零求解完整候选中至少有一项图能量严格超过同工况既有认证窗口参考的工况，执行其中全部4臂。条件仅使用图目标与旧认证参考，不查看新物理结果后挑工况。
- 第一段所有计划任务真实完成、独立科学核验通过后，若任一任务EARLY的完整认证正常能量严格高于该任务完整GUARD，继续预先固定的其余工况任务；第一段任务直接保留，不重跑。
- 没有上述认证改善则停止后续派发，其余全部槽位记`NOT_RUN_GATE_NO_GAIN`并保留，不补零、不删除、不称32项完成。第一段无可靠闭合时是INCONCLUSIVE，停止依赖工作，不当作普通无收益。零候选或没有图改善工况时只完成零求解阶段，明确没有新物理对照。

同一run先冻结全部32，再以独立审计的第一段证据决定是否接续；未用预算不转作新候选、额外等待扫描、换工况或训练。此前362项原池未知保留，本轮不是全池或全空间无解证明。

最多32个冷任务、16384实际点，数值入口上限按`32×3+4×16384=65632`计算。每任务900秒、控制器整体3600秒（含两段之间核验），2并发、单线程数值环境，磁盘12GiB底线/2GiB报告预留及原存储预测。所有初始化、失败、完整进程、模型载入/推理、候选生成、证据共享、GUARD与记录费用计入。部分结果/超时/UNKNOWN/可靠FAIL分开留存，不自动重试。
